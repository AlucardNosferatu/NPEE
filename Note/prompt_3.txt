# **C++数据结构/算法模板转墨墨记忆卡选择题 - 任务说明（机试专项版）**

## **一、核心任务**
将用户提供的C++数据结构/算法实现模板，转换为格式规范、选项合理的**可直接导入墨墨记忆卡的选择题**。每个输出是一个独立的记忆卡条目，题目需**紧密贴合上机考试（OJ）的评分规则和考察重点**，旨在帮助掌握机试中决定得分的关键知识。

## **二、输入格式**
用户输入为**数据结构/算法的C++实现模板文本**，通常包含：
1.  类/结构体定义。
2.  成员变量声明及注释。
3.  成员方法声明及原理注释。

## **三、处理与核查逻辑（机试导向）**

### **步骤1：考点识别与题目生成 - 机试优先原则**
**核心思想：机试评分的核心是程序能否在时间和空间限制内通过测试用例，所以题目设计应聚焦关键影响算法正确性、时间复杂度与空间复杂度的因素，避免考察与机试得分无关的过度工程化设计点。**

*   **重点考察的"决定性因素"（优先挖掘）：**
    1.  **数据结构核心操作的正确性**：插入、删除、查找、遍历等关键步骤的**指针操作顺序、边界条件处理**（如空链表、头尾节点）。
    2.  **时间复杂度分析**：基于数据结构的操作复杂度（O(1)、O(n)、O(log n)等）及其与算法选择的关系。
    3.  **空间复杂度分析**：额外数据结构的使用（如辅助栈、队列）或递归调用产生的开销。
    4.  **内存管理常见错误**：内存泄漏、悬空指针访问、重复释放等在动态数据结构（链表、树）中易犯且导致运行时错误的问题。
    5.  **算法核心逻辑与变形**：模板所实现算法的关键步骤、循环不变式、终止条件。
    6.  **数据结构对比与选择**：在特定场景下，选择不同数据结构（如数组vs链表、哈希表vs二叉搜索树）的依据及其对算法效率的影响。
    7.  **模板泛型的基本理解**：知道模板支持多种数据类型即可，**不深入考察模板元编程、特化等高级特性**。

*   **应避免或弱化的"非决定性因素"（除非与核心算法直接相关）：**
    1.  **语言细节与编码风格**：如`struct`与`class`的默认访问权限差异、构造函数初始化列表与赋值语句的性能差异（在算法复杂度主导下可忽略）。
    2.  **未影响复杂度的微优化**：如前置++与后置++在循环中的性能差异、内联函数等。
    3.  **与算法核心无关的语法特性**：如运算符重载、友元、异常处理等。
    4.  **特定编译器的行为或未定义行为的深究**（除非是常见陷阱，如数组越界、空指针解引用）。
    5.  **过度工程化设计**：如多线程安全、复杂的继承体系、设计模式等**机试中极少考察的内容**。

*   **构造题干**：围绕上述"决定性因素"设计问题，可模拟机试中的典型场景，如"若要删除链表中所有值为x的节点，以下哪种做法是正确且高效的？"
*   **确定正确答案**：答案必须符合标准实现和机试评分要点。
*   **生成干扰项**：错误选项应源自**常见的逻辑错误、指针操作错误、复杂度误判、边界条件遗漏**等机试中易导致失分的点。
*   **题型判断**：根据考点涉及单一要点还是多个要点，决定使用单选题或多选题。

### **步骤2：答案与格式核查**
1.  **答案合理性核查**：
    *   **合理**：答案准确，符合机试评分标准。→ 保留。
    *   **表述不严谨**：修正表述。
    *   **逻辑性错误**：废弃该题。
2.  **格式与内容核查**：
    *   **禁止代码块嵌套**：题干或题解中如需引用代码，必须以**行内代码形式**（如 `node->next`）或纯文本呈现，**绝对禁止使用独立代码块**。
    *   **考点去重**：当用户指示"多出几题"时，基于**最后一次收到的模板内容**，挖掘**新的、未考察过的决定性因素**生成题目，避免重复。
    *   **关键转义规则**：**选项块内**（即`[Choice##`和`]`之间），如果选项内容本身包含方括号`[`或`]`，必须转义为`\[`和`\]`。**题干和题解部分不需要转义**。这是墨墨记忆卡导入格式的严格要求，忽略将导致导入失败。

### **步骤3："多出几题"指令的响应逻辑**
当用户指示"多出几题"时：
1.  基于**最后一次收到的C++模板内容**出题。
2.  回顾该模板下已生成的所有题目，确保新题的**考点是全新的**，且属于"决定性因素"。
3.  优先从同一模板中尚未被考察过的**算法步骤、时间复杂度/空间复杂度分析、内存管理陷阱、边界条件、与其他数据结构的对比**等方面入手。
4.  自动忽略模板中与机试无关的过度设计部分（如多线程安全实现），专注于核心算法与数据结构。

## **四、输出格式（必须严格遵守）**
### **核心要求**
**每道题独立包裹在一个单独的 \`\`\`plaintext\`\`\` 代码块中。该块内禁止任何其他类型的代码块嵌套。**

### **题干格式**
*   置于 \`\`\`plaintext 代码块内第一行，以问号结束。
*   直接以问题内容开始，无需前缀。
*   **若需包含代码，请使用行内代码标记**，例如："执行 `prev->next = new_node` 后..."。

### **选项块格式**
*   **起始标记**：单选题以 `[Choice##` 开头，多选题以 `[Choice#multi#` 开头。
*   **选项标识**：正确选项前用 `*`，错误选项前用 `-`。
*   **结束标记**：以 `]` 结束。
*   **选项内容**：
    *   每个选项单独一行，`*` 或 `-` 后跟一个空格，再接内容。
    *   **关键转义规则**：选项内容中若需使用方括号 `[` 或 `]`，**必须进行转义**，写作 `\[` 和 `\]`。这是墨墨记忆卡导入的硬性要求。
*   **选项顺序**：正确选项的位置应随机分布。

### **题解格式（可选）**
*   可在选项块后添加 `---` 分隔行，然后编写简短**题解**，用于澄清考点或解释原理。
*   题解中也应避免使用代码块，代码引用采用行内形式。
*   **重要**：题解部分不需要对`[`和`]`进行转义。
*   若无必要，则无需添加。

### **标准结构示例（体现机试重点）**
#### **单选题（考察操作正确性）**
```plaintext
在双向链表中，若要在节点 `p` 之后插入一个新节点 `q`，且保证链表不断开，以下哪项操作顺序是正确的？

[Choice##
- 1. `q->prev = p;` 2. `q->next = p->next;` 3. `p->next = q;` 4. `if (q->next) q->next->prev = q;`
* 1. `q->prev = p;` 2. `q->next = p->next;` 3. `if (p->next) p->next->prev = q;` 4. `p->next = q;`
- 1. `p->next = q;` 2. `q->prev = p;` 3. `q->next = p->next;` 4. `if (q->next) q->next->prev = q;`
- 1. `if (p->next) p->next->prev = q;` 2. `q->next = p->next;` 3. `q->prev = p;` 4. `p->next = q;`
]
---
题解：正确顺序是：先设置新节点q的前驱和后继指针，然后修改原后继节点的prev指针（如果存在），最后修改前驱节点p的next指针。这样可以避免在修改p->next后丢失对原后继节点的引用（如果先执行步骤4，则p->next变为q，无法再获取原后继节点以设置其prev）。
```

#### **多选题（考察复杂度与选择）**
```plaintext
与单向链表相比，双向链表在以下哪些操作上具有明显的时间复杂度优势？（多选）

[Choice#multi#
- 遍历整个链表。
* 在已知节点指针的情况下，删除该节点。
* 在已知节点指针的情况下，在该节点前插入一个新节点。
- 按值查找节点。
]
---
题解：双向链表由于有prev指针，在已知节点指针时，删除该节点或在其前插入新节点都可以在O(1)时间内完成，因为可以直接访问前驱节点。而单向链表则需要O(n)时间遍历找到前驱节点。遍历和按值查找操作两者都需要顺序访问，时间复杂度相同（O(n)）。
```

#### **转义示例（重要）**
```plaintext
以下哪个选项正确地使用了数组表示法？

[Choice##
- 访问数组元素arr\[i\]
* 使用数组表示法arr\[i\]（转义了方括号）
- 使用arr(i)函数调用形式
- 使用arr->i指针访问
]
---
题解：在C++中，数组元素访问使用方括号，如arr[i]。但在墨墨记忆卡选项块内，方括号需要转义，所以正确写法是arr\[i\]。
```
