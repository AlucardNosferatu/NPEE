# 3.4 错误注入测试：断言位置与条件设计模式库

## 一、核心理念

错误注入测试在考场环境下的核心是：**针对常见错误模式，预先设计好断言的位置和条件，以便在调试时快速应用**。这是在无法看到具体错误信息时，通过断言触发RE来验证特定错误假设的关键技术。

**与4.2的分工**：
- 4.2（单点断言检查）负责调试流程：一次只启用一个断言，根据RE/WA结果决定下一步。
- 3.4（错误注入测试）负责技术设计：当怀疑某类错误时，应该在哪里、用什么条件进行断言。

## 二、考前准备：记忆常见错误模式的断言设计

### 必须记忆的断言模式（按错误类型分类）

#### 1. 数组/字符串访问错误
- **错误模式**：索引越界、空容器访问、迭代器失效
- **断言位置**：在数组/容器访问之前
- **断言条件**：
  ```cpp
  // 模式A1：简单索引检查
  assert(index >= 0 && index < container.size());
  
  // 模式A2：偏移访问检查（i+1, i-1等）
  assert(i + 1 < n);           // 访问arr[i+1]前
  assert(i - 1 >= 0);          // 访问arr[i-1]前
  
  // 模式A3：空容器检查
  assert(!vec.empty());        // 访问vec[0]或vec.front()前
  assert(!str.empty());        // 访问str[0]前
  
  // 模式A4：迭代器有效性
  assert(it != container.end()); // 解引用迭代器前
  ```

#### 2. 数学运算错误
- **错误模式**：除零、数学函数定义域错误、数值溢出
- **断言位置**：在运算之前
- **断言条件**：
  ```cpp
  // 模式M1：除零保护
  assert(denominator != 0);    // 除法 a / b 前
  assert(modulus != 0);        // 取模 a % b 前
  
  // 模式M2：数学函数定义域
  assert(x >= 0);              // sqrt(x) 前
  assert(x > 0);               // log(x) 前
  
  // 模式M3：数值范围（防止溢出）
  // 注意：断言不能直接防止溢出，但可以检查前提条件
  assert(a <= INT_MAX / b);    // 乘法溢出检查（假设正数）
  ```

#### 3. 递归/循环控制错误
- **错误模式**：递归过深、死循环、循环变量错误
- **断言位置**：递归函数入口、循环开始/结束、循环体内
- **断言条件**：
  ```cpp
  // 模式R1：递归深度控制
  static int depth = 0;
  depth++;
  assert(depth < MAX_RECURSION_DEPTH); // 递归函数入口
  
  // 模式R2：循环变量范围
  assert(loop_counter >= 0 && loop_counter < max_times);
  
  // 模式R3：死循环预防（状态必须变化）
  bool changed = false;
  // ... 循环体内改变状态时设置 changed = true
  assert(changed);  // 循环结束后或下次迭代前检查
  ```

#### 4. 状态一致性错误
- **错误模式**：重复访问、数据不一致、不变量破坏
- **断言位置**：状态改变前后、关键操作前后
- **断言条件**：
  ```cpp
  // 模式S1：访问标记一致性
  assert(!visited[node]);      // 访问节点前
  visited[node] = true;
  assert(visited[node]);       // 标记后立即验证
  
  // 模式S2：数据不变性（如大小不变）
  int original_size = data.size();
  // ... 操作
  assert(data.size() == original_size); // 操作后检查
  
  // 模式S3：有序性保持
  for (int i = 1; i < sorted_part; i++) {
      assert(arr[i-1] <= arr[i]);  // 已排序部分保持有序
  }
  ```

#### 5. 输入/输出错误
- **错误模式**：输入格式错误、输出范围错误、输出格式错误
- **断言位置**：输入后、输出前
- **断言条件**：
  ```cpp
  // 模式IO1：输入有效性
  assert(cin.good());          // 读取后检查
  assert(n >= 1 && n <= 100000); // 题目约束验证
  
  // 模式IO2：输出范围验证
  assert(result >= 0 && result <= 1e9); // 根据题目约束
  
  // 模式IO3：输出格式正确性
  // 例如：保证输出数量与题目要求一致
  // assert(output_count == n); // 如果应该输出n个数
  ```

## 三、考场应用：快速匹配错误症状到断言模式

### 症状-模式对应表（考前记忆）

| 你观察到的症状或怀疑的错误 | 应该使用的断言模式 | 示例代码 |
|-------------------------|-------------------|----------|
| 程序访问数组时崩溃或WA | 模式A1（索引检查） | `assert(i >= 0 && i < n);` |
| 循环中访问`arr[i+1]`可能越界 | 模式A2（偏移检查） | `assert(i+1 < n);` |
| 容器可能为空时访问首元素 | 模式A3（空容器检查） | `assert(!vec.empty());` |
| 使用迭代器可能已到end | 模式A4（迭代器检查） | `assert(it != vec.end());` |
| 除法运算可能除零 | 模式M1（除零保护） | `assert(denominator != 0);` |
| 递归函数可能栈溢出 | 模式R1（递归深度） | `assert(depth < 1000);` |
| 节点可能被重复访问 | 模式S1（访问标记） | `assert(!visited[node]);` |
| 输入可能不符合约束 | 模式IO1（输入验证） | `assert(n >= 1 && n <= 100000);` |

### 应用流程（与4.2结合）：
1. **识别症状**：根据程序行为（WA、RE）或代码审查，怀疑某类错误。
2. **选择模式**：根据上表选择对应的断言模式。
3. **实现断言**：在代码的合适位置插入断言（使用条件编译控制，如`#if CHECK_POINT == 1`）。
4. **单点测试**：使用4.2的方法，启用该断言，提交测试。
5. **结果分析**：若RE，则证实错误，修复；若WA，则可能错误不在该点，继续。

## 四、断言设计原则（考场优化版）

1. **一个断言只检查一个条件**：便于定位。如果多个条件，分开写多个断言。
2. **断言位置紧邻可疑操作**：在可能出错的操作之前立即检查。
3. **断言条件尽可能简单**：复杂条件可能本身有bug，且考场无法得知哪个子条件失败。
4. **使用描述性消息（可选）**：`assert(cond && "error message");` 虽然看不到，但可帮助自己记忆。
5. **避免副作用**：断言内不要改变程序状态。

## 五、考前快速参考卡

在草稿纸上预先写下：

```
=== 断言模式速查 ===
1. 索引越界：assert(i>=0 && i<size)
2. 偏移访问：assert(i+1<size) 或 assert(i-1>=0)
3. 空容器：assert(!cont.empty())
4. 迭代器：assert(it!=end)
5. 除零：assert(denom!=0)
6. 递归深度：static int d=0; d++; assert(d<1000)
7. 重复访问：assert(!visited[node])
8. 输入验证：assert(n>=min && n<=max)
9. 输出范围：assert(result>=min && result<=max)
```

## 六、示例：应用断言模式库调试

### 问题：图遍历中可能重复访问节点
```cpp
void dfs(int node, vector<vector<int>>& graph, vector<bool>& visited) {
    // 怀疑点：节点可能被重复访问，导致死循环或错误
    // 应使用模式S1：访问标记一致性
    
    #if CHECK_POINT == 1
    assert(!visited[node]);  // 访问前应未访问
    #endif
    
    visited[node] = true;
    
    for (int neighbor : graph[node]) {
        dfs(neighbor, graph, visited);
    }
}
```
**测试**：启用`CHECK_POINT=1`，若RE则证实有重复访问，需要检查递归条件或图是否有环。

## 七、常见陷阱与避免

### 陷阱1：断言条件过于复杂
```cpp
// 错误：复杂条件，无法知道哪个子条件失败
assert(i >= 0 && i < n && arr[i] != 0 && arr[i] > -100);

// 正确：拆分成多个断言
assert(i >= 0 && i < n);
assert(arr[i] != 0);
assert(arr[i] > -100);
```

### 陷阱2：断言位置不当
```cpp
// 错误：断言放在访问之后
int val = arr[i];
assert(i >= 0 && i < n);  // 太晚了，如果越界已经崩溃

// 正确：断言放在访问之前
assert(i >= 0 && i < n);
int val = arr[i];
```

### 陷阱3：断言影响性能（考场中不重要）
在考场中，性能不是首要考虑，正确性优先。断言可以留在调试版本中，提交前移除即可。

**关键要点**：
1. **分门别类**：将错误分为数组访问、数学运算、递归循环、状态一致性、输入输出等类型。
