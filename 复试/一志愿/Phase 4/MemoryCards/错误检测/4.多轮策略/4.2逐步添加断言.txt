# 4.2 第二阶段：逐步添加断言（考场优化版）

## 一、核心理念

在考场环境下，逐步添加断言的核心是：**每次只启用一个断言，通过RE/WA变化精确判断该点是否正确**。由于看不到具体错误信息，必须通过单一断言触发RE来判断问题所在。

## 二、考场限制下的调整

### 关键限制：
1. **看不到断言信息**：无法知道哪个断言触发或具体条件
2. **RE来源不明确**：多个断言同时启用时，无法区分哪个失败
3. **提交次数有限**：需要最小化提交次数

### 调整策略：
- **单点原则**：一次只启用一个断言
- **顺序覆盖**：按逻辑顺序检查关键点
- **结果分析**：通过RE触发判断该点有问题

## 三、考场实施流程

### 准备阶段（考前记忆）：
1. 设计3-5个关键检查点
2. 准备断言开关宏
3. 建立结果记录表格（草稿纸上）

### 执行流程：
```
步骤1：编写完整代码，所有断言默认禁用
步骤2：提交一次，得到WA（基线）
步骤3：启用检查点1的断言，提交
步骤4：记录结果（RE/WA）
步骤5：禁用检查点1，启用检查点2，提交
步骤6：重复直到找到错误点
步骤7：修复错误，重新测试
```

## 四、技术实现：单点断言控制

### 基础模式：
```cpp
// 定义检查点开关
#define CHECK_POINT 0  // 0=无，1=检查点1，2=检查点2...

int main() {
    // 读取输入
    
    // 检查点1：输入验证
    #if CHECK_POINT == 1
    assert(input_valid());
    #endif
    
    // 检查点2：算法入口
    #if CHECK_POINT == 2
    assert(initial_condition());
    #endif
    
    // 主算法逻辑
    
    // 检查点3：输出验证
    #if CHECK_POINT == 3
    assert(output_valid());
    #endif
    
    return 0;
}
```

### 检查点设计原则（考场版）：
1. **检查点要少而精**：3-5个关键点足够
2. **检查条件要简单**：确保触发RE时能明确推断原因
3. **检查点要独立**：每个点检查一个独立假设

## 五、检查点选择策略

### 推荐检查点顺序：
```
第1点：输入验证（数组边界、范围检查）
第2点：算法初始化（初始状态是否正确）
第3点：主循环入口（第一次迭代检查）
第4点：计算结果（关键变量状态）
第5点：输出验证（最终结果合理性）
```

### 示例：排序算法的检查点
```cpp
void sort_with_checks(vector<int>& arr) {
    int n = arr.size();
    
    // 检查点1：输入有效性
    #if CHECK_POINT == 1
    assert(n >= 0 && n <= MAX_SIZE);
    for (int x : arr) assert(x >= MIN_VAL && x <= MAX_VAL);
    #endif
    
    // 检查点2：循环边界（第一次迭代）
    #if CHECK_POINT == 2
    assert(0 < n);  // 确保至少有一个元素
    #endif
    
    for (int i = 0; i < n; i++) {
        // 检查点3：索引有效性
        #if CHECK_POINT == 3
        assert(i >= 0 && i < n);
        #endif
        
        // 排序逻辑...
    }
    
    // 检查点4：排序结果
    #if CHECK_POINT == 4
    for (int i = 1; i < n; i++) {
        assert(arr[i-1] <= arr[i]);
    }
    #endif
}
```

## 六、结果分析与错误定位

### 判断规则：
```
情况A：WA → RE（检查点启用后）
  结论：该检查点检测到问题，错误可能在相关区域
  行动：修复该区域问题
  
情况B：WA → WA（检查点启用后）
  结论1：该检查点条件成立
  结论2：错误在其他地方
  行动：继续下一个检查点
  
情况C：RE → WA（修复后）
  结论：修复成功，继续查找其他错误
  行动：继续下一个检查点
```

### 草稿纸记录模板：
```
题目：________
基线：CHECK=0 → WA

检查点1（输入验证）：CHECK=1 → [WA/RE]
分析：________________

检查点2（初始化）：CHECK=2 → [WA/RE]
分析：________________

检查点3（主逻辑）：CHECK=3 → [WA/RE]
分析：________________

检查点4（输出）：CHECK=4 → [WA/RE]
分析：________________

修复记录：________________
最终结果：________________
```

## 七、时间管理策略

### 时间分配（总时间120分钟）：
```
阶段1：编码与基线测试 - 30分钟
阶段2：逐步断言调试 - 40分钟
阶段3：修复与验证 - 20分钟
阶段4：最终检查 - 10分钟
预留缓冲 - 20分钟
```

### 每个检查点的成本：
```
思考与设置：2分钟
提交与等待：2分钟
分析与记录：1分钟
总计：5分钟/检查点
```

### 进度控制：
```
预期：最多检查5个点（25分钟）
如果时间不足，优先检查：
  1. 输入验证
  2. 最核心的算法逻辑
  3. 输出验证
```

## 八、常见错误的检查点设计

### 数组越界错误：
```cpp
// 检查点：数组访问前
#if CHECK_POINT == 1
assert(index >= 0 && index < array.size());
#endif
```

### 除零错误：
```cpp
// 检查点：除法前
#if CHECK_POINT == 2
assert(denominator != 0);
#endif
```

### 逻辑错误（条件判断）：
```cpp
// 检查点：条件分支处
#if CHECK_POINT == 3
assert(condition == expected_condition);
#endif
```

### 边界条件错误：
```cpp
// 检查点：特殊值处理
#if CHECK_POINT == 4
if (n == 0) {
    assert(result == expected_empty_result);
}
#endif
```

## 九、考场应急方案

### 方案A：时间不足时（<10分钟）
```
跳过逐步断言，直接：
1. 添加最可能出错的检查点
2. 提交一次
3. 根据结果决定修复或提交
```

### 方案B：多次RE无法定位时
```
如果多个检查点都触发RE：
1. 可能基础代码有严重错误
2. 考虑重写核心部分
3. 或提交当前版本（可能部分分）
```

### 方案C：所有检查点都WA（无RE）
```
如果所有检查点都WA（没有触发RE）：
1. 错误可能在检查点未覆盖的区域
2. 或错误是算法思路错误
3. 重新审视算法逻辑
```

## 十一、示例：调试二分查找

### 初始代码（有错误）：
```cpp
int binary_search(vector<int>& arr, int target) {
    int left = 0, right = arr.size();  // 错误：应该是arr.size()-1
    
    while (left < right) {  // 错误：应该是left <= right
        int mid = (left + right) / 2;
        
        if (arr[mid] == target) return mid;
        else if (arr[mid] < target) left = mid;  // 错误：应该是mid+1
        else right = mid;  // 错误：应该是mid-1
    }
    
    return -1;
}
```

### 逐步断言调试：
```
基线：CHECK=0 → WA

检查点1：输入验证
#if CHECK_POINT == 1
assert(!arr.empty());
#endif
结果：WA → 输入没问题

检查点2：初始边界
#if CHECK_POINT == 2
assert(left <= right);
#endif
结果：RE → 边界有问题！发现right初始值错误

修复：right = arr.size()-1;

检查点3：循环条件
#if CHECK_POINT == 3
assert(left <= right);  // 检查循环内条件
#endif
结果：WA → 条件可能没问题

检查点4：mid计算
#if CHECK_POINT == 4
assert(mid >= left && mid <= right);
#endif
结果：WA → mid计算正确

检查点5：边界更新
#if CHECK_POINT == 5
if (arr[mid] < target) {
    assert(left == mid + 1);  // 更新后检查
}
#endif
结果：RE → 边界更新错误！

修复：left = mid + 1; right = mid - 1;
最终：AC
```

## 十二、总结：考场最佳实践

### 核心原则：
**一次只测试一个假设，通过RE触发判断假设是否正确**

### 实施步骤：
1. **设计检查点**：考前准备3-5个标准检查点
2. **顺序测试**：按逻辑顺序启用每个检查点
3. **记录结果**：在草稿纸上记录每次提交的结果
4. **分析修复**：根据RE触发点修复错误
5. **最终清理**：删除所有断言，提交最终代码

### 预期效果：
通过3-5次提交，有较高概率定位到主要错误点。

### 限制条件：
- 需要精心设计检查点
- 每个检查点必须简单明确
- 需要良好的时间管理

### 最后提醒：
考场中，**系统化比随机猜测更有效**。逐步添加断言方法提供了结构化的调试流程，即使信息有限也能有效定位错误。

---

**结论**：原4.2节的逐步添加断言策略在考场环境下**需要简化调整**，但核心思想依然有效。调整为**单点顺序测试法**后，可以在考场限制下有效进行调试。
