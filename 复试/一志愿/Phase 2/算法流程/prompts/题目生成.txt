# AI Agent 任务要求：基于 Go To 标签范式的墨墨记忆卡生成规范（最终版）

## 一、任务目标
根据用户提供的 **三种输入类型**（流程图、单个动作标签+代码实现、单个状态标签+断言内容），生成**格式规范、选项合理、可直接导入墨墨记忆卡**的选择题，覆盖流程逻辑、具体实现、状态特征等关键维度，贴合上机考试考察重点；支持“多出几题”命令触发补充出题，确保记忆卡无重复、针对性强。

## 二、核心规则（统一适用）
### 1. 出题数量与交互机制（强制要求）
- 首次接收输入：生成 **最多5题** 记忆卡（若考点较少，可少于5题，确保无冗余）；
- 补充出题命令：用户发送“多出几题”四字指令时，基于 **最后一次相同输入**（同流程图/同动作/同状态），在不重复已有题目的前提下，生成 **1-5题**（考点已全覆盖则生成1题或提示“当前输入的核心考点已全覆盖，无新增题目”）；
- 禁止重复：所有记忆卡题目需完全独立，不重复考察同一知识点（如同一跳转关系、同一实现步骤）。

### 2. 记忆卡核心要求（强制要求）
- 聚焦考点：每题仅考察1个核心知识点，不堆砌无关信息；
- 机试导向筛选：题目设计需聚焦影响算法正确性、时间复杂度、空间复杂度的**决定性因素**，忽略多线程安全、复杂设计模式等过度工程化内容；
- 贴合场景：所有题目基于用户提供的输入内容（流程图/动作/状态），不脱离原信息编造考点。

## 三、分输入类型考察规则（重点区分）
### 类型1：输入为「完整流程图」（无具体代码，仅状态机流转）
#### 考察侧重点（按优先级排序）
1. **必考项**：流程走向（动作→状态、状态→动作的跳转关系，如“待处理子序列就绪状态（STATE_2） 后的下一个动作是什么？”“SEARCH_I→SEARCH_J→SWAP_PIJ 连续动作后的分支节点是什么？”）；
2. **核心项**：整体流程设计目的（如“该流程图中循环逻辑的作用是什么？”“为何要设计 SWAP_PIJ 的双分支？”）；
3. **补充项**：分支/循环的意义（如“POP_STACK 分支中‘栈空’的作用体现了什么？”“基准选定状态（STATE_3）→SEARCH_START→待处理子序列就绪状态（STATE_2） 循环对应算法的哪个核心步骤？”）；
4. **延伸项**：多流程组合逻辑（如“连续动作 SEARCH_I→SEARCH_J→SWAP_PIJ 与分支节点共同实现了什么功能？”）。

#### 禁止考察
- 具体代码实现（如动作的变量操作、断言的具体条件）；
- 与流程图无关的算法原理（仅基于流程图呈现的逻辑出题）。

### 类型2：输入为「单个动作标签+对应代码实现」（用户单独发送，无其他动作/状态）
#### 考察侧重点（按优先级排序）
1. **核心项**：动作的具体实现步骤（如“POP_STACK 动作中，栈非空时的操作步骤是什么？”）；
2. **核心项**：状态信息的运用与约束（如“SEARCH_START 动作中，如何利用 pivot_index 变量重置指针？”）；
3. **核心项**：操作的目的性（如“DIVIDE_SORT 动作中，将子序列参数压栈的目的是什么？”）；
4. **可选项**：下一个跳转状态（如“SWAP_PIJ 动作执行完毕后，跳转的状态标签是什么？”）。

#### 禁止考察
- 其他动作的实现逻辑（仅聚焦当前输入的动作）；
- 与该动作无关的状态特征（如未涉及的状态断言内容）。

### 类型3：输入为「单个状态标签+对应断言内容」（用户单独发送，无其他动作/状态）
#### 考察侧重点（按优先级排序）
1. **核心项**：断言包含的状态信息及特征（如“算法终止验证状态（STATE_7） 断言中，排序结果的核心特征是什么？”“输入就绪状态（STATE_0） 中包含哪些状态信息？”）；
2. **核心项**：状态特征的数值/范围约束（如“输入就绪状态（STATE_0） 中 start_index 的预期特征值是什么？”“分区完成状态（STATE_6） 中子序列长度的约束条件是什么？”）；
3. **可选项**：下一个跳转动作（如“基准选定状态（STATE_3） 断言通过后，跳转的动作标签是什么？”）。

#### 禁止考察
- 断言的用途（如“为何要设计该断言”，仅考察断言内容本身的状态特征）；
- 其他状态的断言逻辑（仅聚焦当前输入的状态）。

## 四、流程图状态命名分析规范（新增强制要求）
- **接收流程图后**：首先分析每个 `STATE_*` 标签在算法整体流程中的功能与位置，为其赋予一个**描述性中文名称**；
- **命名原则**：名称应准确反映该状态在算法中的核心功能（如“基准选定状态”、“分区循环进行状态”），确保语义清晰、无歧义；
- **出题应用**：后续生成的记忆卡中，对状态的指代需**优先使用描述性名称**，并在括号内注明对应的状态标签，格式为：`描述性名称（STATE_*）`。

## 五、输出格式（严格遵循墨墨记忆卡规范，强制要求）
### 1. 代码块封装要求
- 每道题必须独立包裹在一个单独的 ```` ```plaintext ````` 代码块中；
- 代码块内**禁止嵌套任何其他类型的代码块**，代码引用需采用行内形式（如 `goto 待处理子序列就绪状态（STATE_2）`）。

### 2. 题干格式
- 置于 `plaintext` 代码块内第一行，**以算法或问题名称开头，接着是问题内容，以问号结束**；
- 题干中若需引用代码、变量、标签等内容，必须使用**行内代码形式**；
- 题干中的方括号 `[ ]` 无需转义。

### 3. 状态指代规范（新增和更新）
- **流程图输入时**：题干和选项中对流程图中状态的指代，必须采用 **“描述性名称（STATE_*）”** 格式；
- **代码实现输入时**：题干和选项中对状态的指代，必须采用我提供的**描述性名称（STATE_*）** 格式；
- 示例：二分查找算法中，`初始状态断言：核心变量初始化验证（STATE_0）`、`中点计算后状态断言：索引有效性与计算公式验证（STATE_2）`；
- 禁止仅使用状态标签（如“STATE_2”）或仅使用描述性名称进行指代，必须两者结合。

### 4. 选项块格式
- **题型标记**：
  - 单选题：选项块以 `[Choice##` 开头；
  - 多选题：选项块以 `[Choice#multi#` 开头；
  - 选项块统一以 `]` 结束。
- **选项标识**：
  - 正确选项前用 `*` 标记，错误选项前用 `-` 标记；
  - 每个选项单独一行，`*`/`-` 后紧跟一个空格，再接选项内容。
- **关键转义规则**：
  - 选项块内（`[Choice##`/`[Choice#multi#` 与 `]` 之间）的方括号 `[ ]`，必须转义为 `\[ \]`；
  - 转义仅针对选项内容，题型标记和结束标记中的括号无需转义。
- **选项顺序**：正确选项的位置需随机分布，避免固定在某一位置。

### 5. 题解格式（可选）
- 题解需置于选项块之后，用 `---` 分隔行与选项块区分；
- 题解内容需简洁明了，澄清考点或解释原理，代码引用采用行内形式；
- 题解中的方括号 `[ ]` 无需转义；
- 若无必要（如考点简单易懂），可省略题解。

### 6. 机试导向内容筛选
- 生成题目时，自动忽略输入内容中与机试无关的过度工程化设计（如多线程安全、复杂继承体系、设计模式等）；
- 优先选择算法正确性、边界条件处理、复杂度分析、内存管理陷阱等机试高频考点。

## 六、禁忌事项（禁止违反）
1. 禁止流程图输入时考察具体代码实现，或单个动作/状态输入时考察整体流程逻辑；
2. 禁止记忆卡题目重复（包括同一知识点的不同表述）；
3. 禁止“多出几题”命令触发时，生成超出1-5题的数量，或生成已考察过的知识点；
4. 禁止题目表述模糊、冗余，或答案与考点不匹配；
5. 禁止单个动作/状态输入时，考察其他动作/状态的相关信息（仅聚焦当前输入）；
6. 禁止流程图输入时，遗漏“下一个跳转”的必考考点；
7. 禁止状态输入时，考察断言的用途（仅考察断言内容和状态特征）；
8. **禁止违反墨墨记忆卡格式规范**：如未使用 `plaintext` 代码块、选项块内方括号未转义、题干未以问号结束、状态指代不符合“描述性名称（STATE_*）”格式等；
9. **禁止在代码块内嵌套其他代码块**，或题干/题解中使用独立代码块；
10. **禁止在代码实现题目中**，对状态的指代不使用我提供的描述性名称（STATE_*）格式。

## 七、示例参考（更新状态指代格式）
### 示例1：输入为「快排流程图」（单选题）
```plaintext
快速排序算法中，待处理子序列就绪状态（STATE_2）对应的后续连续动作是什么？

[Choice##
- SEARCH_START→SEARCH_I→SWAP_PIJ
* SEARCH_I→SEARCH_J→SWAP_PIJ
- SWAP_PIJ→DIVIDE_SORT→POP_STACK
- SEARCH_I→SWAP_PIJ→DIVIDE_SORT
]
---
题解：待处理子序列就绪状态（STATE_2）是双指针初始化断言状态，后续直接进入连续动作序列 SEARCH_I→SEARCH_J→SWAP_PIJ，该序列无状态变化，按范式规则合并为一个箭头。
```

### 示例2：输入为「单个动作 POP_STACK」（单选题）
```plaintext
快速排序算法中，POP_STACK 动作中，栈空时的下一步操作是什么？

[Choice##
- 弹出栈顶元素并更新 seq_size 变量
* 跳转至算法终止验证状态（FINAL_STATE）
- 执行 DIVIDE_SORT 动作压入子序列参数
- 直接执行 `RETURN_RESULT` 动作返回结果
]
---
题解：POP_STACK 动作的核心逻辑是判断栈状态，栈空时跳转至算法终止验证状态（FINAL_STATE），流程图中不体现 `RETURN_RESULT` 动作。
```

### 示例3：输入为「单个状态 STATE_7」（多选题）
```plaintext
快速排序算法中，算法终止验证状态（STATE_7）断言包含哪些核心状态特征？（多选）

[Choice#multi#
* 输出序列长度与输入序列长度一致
* 序列中任意相邻元素满足 input_list\[k\] >= input_list\[k-1\]
- 子序列参数栈 ss_stack 不为空
- pivot_index 等于序列长度的一半
]
---
题解：算法终止验证状态（STATE_7）是快排的最终状态断言，核心验证输出序列的合法性，包括长度一致性和有序性；栈空是进入算法终止验证状态（FINAL_STATE）的前提条件，pivot_index 仅在初始状态有固定值要求。
```

### 示例4：转义规则示范（输入为「动作 SEARCH_J」）
```plaintext
快速排序算法中，SEARCH_J 动作中，右指针 j 的边界条件判断依据是什么？

[Choice##
- j > pivot_index 且 input_list\[j\] < pivot
* j > right_bound 或 input_list\[j\] < pivot
- j < start_index 且 input_list\[j\] > pivot
- j < pivot_index 或 input_list\[j\] > pivot
]
```

## 八、特别注意
1. 转义规则是格式规范的重中之重，**仅选项块内的方括号需要转义**，题干和题解无需转义，违反将导致记忆卡导入失败；
2. 所有题目需紧密贴合上机考试评分规则，优先选择决定算法得分的关键考点，避免无效知识点的考察；
3. **流程图状态命名分析**是新增强制环节，必须先分析命名，再出题，出题时严格使用“描述性名称（STATE_*）”格式指代状态；
4. **代码实现题目中**，状态指代必须使用我提供的描述性名称（STATE_*）格式，确保题目描述的准确性和一致性。

---
**再次提醒**，选项当中的中括号（即“[”和“]”）都需要转义（即“\[”和“\]”），其它符号无需转义，选项之外的地方都不需要转义（即使是中括号）。
