# 软件测试 三者交集核心总结
（行内必知重点技术 + 计算机专业强关联 + 易懂好记）
## 一、软件测试标准全流程
1. 测试需求分析
    行内测试起始环节，关联计算机软件需求文档，核心是梳理软件功能、性能、交互等测试范围，明确要测什么、不测什么，对齐开发的功能逻辑设计。
2. 测试计划制定
    行业必备流程，关联计算机项目管理，确定测试时间、人员分工、测试环境、测试工具，规划整体测试节奏，匹配软件开发迭代周期。
3. 测试执行落地
    核心实操环节，对应计算机程序运行验证，按照设计方案部署测试环境，执行测试操作，验证软件功能是否符合需求、程序是否正常运行。
4. 测试总结与交付
    行业收尾标准，关联计算机项目上线流程，汇总测试结果、缺陷修复情况，输出测试报告，判断软件是否达到上线/交付标准。
5. 回归测试闭环
    行内必做环节，关联程序bug修复逻辑，开发修复缺陷后，重新执行测试用例，验证缺陷已解决且未引入新问题，保证软件稳定性。

## 二、主流核心软件测试类型
1. 功能测试
    行业最基础必测类型，关联计算机软件逻辑功能，验证软件的按钮、输入、跳转、数据处理等功能是否按需求实现，不关注内部代码逻辑。
2. 兼容性测试
    行业通用测试项，关联计算机软硬件环境，测试软件在不同操作系统、浏览器、设备、分辨率下能否正常运行，无适配异常。
3. 性能测试
    中高阶必测技术，关联计算机系统资源调度，验证软件在高并发、大数据量下的响应速度、卡顿情况、CPU/内存占用，是否满足使用要求。
4. 接口测试
    行业后端核心测试，关联计算机网络与数据交互，测试软件前后端、模块之间的接口数据传输是否正常，参数传递、返回结果是否准确。
5. 安全测试
    行业关键测试项，关联计算机信息安全，检测软件是否存在漏洞、数据泄露、越权访问、SQL注入等安全风险，保障数据与系统安全。

## 三、核心测试用例设计方法
1. 等价类划分法
    行内入门必备方法，关联计算机数据逻辑分类，将输入数据划分为有效、无效等价类，选取代表性数据测试，减少冗余用例，覆盖核心数据场景。
2. 边界值分析法
    行业高频使用方法，关联计算机程序边界逻辑，重点测试数据的最大、最小、临界值，程序最容易在边界处出现bug，针对性验证。
3. 场景法
    行业实用设计方法，关联计算机用户操作流程，模拟用户真实使用软件的完整业务流程，覆盖正常、异常操作场景，贴合实际使用逻辑。
4. 错误推测法
    经验型核心方法，关联计算机bug常见规律，基于测试经验推测软件易出错的位置，设计针对性测试用例，快速定位潜在问题。
5. 判定表法
    逻辑型设计方法，关联计算机条件判断逻辑，针对多条件、多结果的功能，梳理条件组合，覆盖所有逻辑分支，避免逻辑漏洞。

## 四、软件缺陷管理与验证
1. 缺陷提交规范
    行内标准操作，关联计算机项目协作，清晰描述缺陷的复现步骤、环境、现象、优先级，保证开发能快速复现并定位问题。
2. 缺陷分级管理
    行业通用规则，关联计算机软件影响程度，按缺陷严重程度分为致命、严重、一般、轻微，优先修复核心致命问题，保障软件核心功能。
3. 缺陷跟踪流转
    行业核心流程，关联开发测试协作，跟踪缺陷从提交、确认、修复、复测、关闭的全流程，确保每个问题都有闭环处理。
4. 缺陷复测验证
    必做实操环节，关联程序修复逻辑，开发修复后严格按复现步骤复测，确认缺陷解决，同时检查周边功能无连带问题。
5. 缺陷数据分析
    进阶管理技能，关联计算机项目优化，统计缺陷数量、类型、分布，分析问题根源，反馈给开发优化代码逻辑，提升软件质量。

## 五、基础自动化测试入门
1. 自动化测试适用场景
    行业趋势核心，关联计算机重复执行逻辑，针对回归测试、固定流程、大批量数据测试，用脚本替代手动操作，提升测试效率。
2. 主流自动化测试工具
    行内必知工具，关联计算机编程基础，Web测试用Selenium、接口测试用Postman/JMeter、APP测试用Appium，入门简单易上手。
3. 测试脚本基础编写
    计算机专业强关联，基于Python/Java等编程语言，编写简单自动化脚本，实现点击、输入、校验等操作的自动执行。
4. 自动化测试用例维护
    行业实操要点，关联软件迭代更新，软件功能变更后同步修改自动化脚本，保证脚本与软件功能匹配，避免脚本失效。
5. 自动化与手动测试结合
    行业最优方案，核心功能、复杂场景用手动测试，重复流程用自动化，兼顾测试覆盖率与效率，贴合实际项目需求。
