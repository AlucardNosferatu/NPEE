# 3.2 内存检查（考场优化版）

## 一、核心理念

在考场环境下，内存检查的核心是**预防性编码和关键位置断言**。通过编码规范避免常见内存错误，并在怀疑点添加简单断言触发RE来验证假设。

## 二、考场可用的内存安全编码规范

### 1. 使用标准容器代替裸数组
```cpp
// 推荐做法
vector<int> arr(n);  // 而不是 int* arr = new int[n];
vector<vector<int>> mat(n, vector<int>(m));

// 如果需要动态分配，优先使用智能指针
auto ptr = make_unique<int[]>(n);  // C++14+
```

### 2. 初始化所有变量
```cpp
int x = 0;           // 总是初始化
string s = "";       // 明确初始化
vector<int> v;       // 默认构造
bool flag = false;   // 明确布尔值
```

### 3. 避免复杂指针操作
```cpp
// 使用vector索引代替指针算术
for (int i = 0; i < arr.size(); i++)  // 而不是 *(arr + i)
    arr[i] = i;
```

## 三、考场断言检查模式

### 1. 边界检查宏（最重要）
```cpp
#define MEM_CHECK 0  // 0=无，1=边界检查，2=空容器检查

#if MEM_CHECK == 1
#define CHECK_BOUNDS(arr, idx) assert((idx) >= 0 && (idx) < (arr).size())
#else
#define CHECK_BOUNDS(arr, idx)
#endif
```

### 2. 空容器检查宏
```cpp
#if MEM_CHECK == 2
#define CHECK_EMPTY(cont) assert(!(cont).empty())
#else
#define CHECK_EMPTY(cont)
#endif
```

### 3. 指针有效性检查（如果需要指针）
```cpp
#if MEM_CHECK == 3
#define CHECK_NULL(ptr) assert((ptr) != nullptr)
#else
#define CHECK_NULL(ptr)
#endif
```

## 四、常见内存错误检查策略

### 错误1：数组越界（最高频）
```cpp
// 可疑代码
for (int i = 0; i <= n; i++) {  // 怀疑越界
    arr[i] = i;  // 可能访问arr[n]
}

// 添加检查
for (int i = 0; i <= n; i++) {
    CHECK_BOUNDS(arr, i);  // 启用MEM_CHECK=1
    arr[i] = i;
}
```

### 错误2：空容器访问
```cpp
// 可疑代码
int first = vec[0];  // vec可能为空

// 添加检查
CHECK_EMPTY(vec);    // 启用MEM_CHECK=2
int first = vec[0];
```

### 错误3：迭代器失效（使用索引代替）
```cpp
// 避免使用复杂迭代器
for (int i = 0; i < vec.size(); i++) {
    // 用索引而不是迭代器
}
```

## 五、考场实施流程

### 步骤1：基线编码
编写符合安全规范的代码，不使用内存检查宏。

### 步骤2：怀疑点识别
根据代码审查，识别1-2个最可能的内存错误点。

### 步骤3：单点检查
```cpp
// 启用一个检查点
#define MEM_CHECK 1  // 或2, 3
// 提交测试，记录结果
// RE → 该点有问题；WA → 可能没问题
```

### 步骤4：修复与验证
修复发现的问题，禁用检查，重新测试。

## 七、考前记忆要点

### 必须记住的规范：
1. **用vector代替数组**
2. **用string代替char[]**
3. **初始化所有变量**
4. **检查循环边界**（特别注意<=与<的区别）

### 必须记住的断言模式：
```cpp
// 三个核心断言
assert(index >= 0 && index < size);   // 边界
assert(!container.empty());           // 空容器
assert(pointer != nullptr);           // 空指针
```

## 八、示例调试过程

### 问题代码：
```cpp
int sum_first_last(vector<int>& arr) {
    // 潜在错误：arr可能为空
    return arr[0] + arr[arr.size()-1];
}
```

### 调试步骤：
```
1. 基线：无检查 → RE

2. 添加空容器检查：
   #define MEM_CHECK 2
   CHECK_EMPTY(arr);  // 在访问前
   结果：RE → 证实arr可能为空

3. 修复：
   if (arr.empty()) return 0;

4. 重新测试：MEM_CHECK=0 → WA/AC
```

## 九、考场时间管理

### 内存检查时间分配：
```
总时间：120分钟
编码规范执行：额外1-2分钟
怀疑点识别：2分钟
单点检查与修复：5-8分钟/点
总计：10-15分钟
```

### 快速决策：
```
如果时间紧张（<10分钟）：
1. 只检查最重要的边界访问
2. 修复明显问题后提交
```

## 十、总结

### 核心原则：
**预防为主，检查为辅，单点验证**

### 实施步骤：
1. **编码时**：遵循安全规范
2. **怀疑时**：添加简单断言
3. **验证时**：启用单个检查点，通过RE触发判断
4. **修复后**：禁用检查，提交最终代码

### 检查优先级：
1. 数组/vector边界访问
2. 空容器访问
3. 指针有效性（如果使用指针）

通过预防性编码和关键点断言，可以在考场环境下有效避免和检测常见内存错误。
