# **C++步骤实现记忆卡生成 - 任务说明（goto+标签范式版）**

## **一、核心任务**
将用户提供的基于**goto+标签范式实现的C++算法步骤代码**，转换为**可直接导入墨墨记忆卡的选择题**，旨在帮助训练者**掌握算法中每个具体步骤的内部实现细节、编码技巧和常见陷阱**。

## **二、输入格式**
用户输入为**使用goto语句和标签模拟流程控制的C++代码**，特征如下：
1. 使用标签（如`STEP1:`、`PARTITION:`）明确标记流程图中的每个步骤
2. 使用goto语句在标签间跳转，模拟流程图的箭头流向
3. 每个标签对应的代码块实现该步骤的具体操作
4. 代码可能包含变量操作、条件判断、循环、函数调用等

## **三、处理与核查逻辑（步骤实现导向）**

### **步骤1：代码解析与题目生成 - 细节优先原则**
**核心思想：训练目标是掌握每个步骤的具体实现细节，而非整体流程。题目应聚焦于步骤内部的代码逻辑、变量操作、边界条件和常见编码错误。**

*   **重点考察的"实现细节"（按优先级）：**
    1.  **标签内代码的具体操作**：变量如何初始化、更新？进行了哪些计算？
    2.  **条件判断的精确含义**：if/switch的条件表达式、短路逻辑、边界值处理。
    3.  **循环控制的细节**：循环变量的初始化、终止条件、迭代方式。
    4.  **数据结构的操作**：数组索引、指针/引用操作、链表/树节点操作。
    5.  **函数调用与参数传递**：参数类型（值/引用/指针）、返回值处理、副作用。
    6.  **资源管理与内存安全**：动态内存分配/释放、空指针检查、防止泄漏。
    7.  **goto跳转的逻辑**：理解跳转的条件和目的，注意跳转是否跳过关键操作。
    8.  **常见编码陷阱**：差一错误、符号错误、更新顺序错误、缺少边界检查。

*   **应避免或弱化的内容：**
    1.  算法的整体流程顺序（应由流程图记忆卡负责）。
    2.  与当前步骤无关的其他步骤细节。
    3.  纯理论性的算法复杂度分析（除非实现中涉及直接影响性能的操作）。
    4.  过度工程化的设计模式或架构。

*   **构造题干**：直接针对具体标签内的代码提问，例如：“在标签`MERGE:`的代码中，临时数组`temp`的作用是什么？”
*   **确定正确答案**：答案必须严格符合代码的实际行为。
*   **生成干扰项**：错误选项应源自**常见的编码错误和误解**，如：
        *   变量初始化错误（如未初始化、错误初始值）。
        *   条件判断的边界错误（如使用`<`而不是`<=`）。
        *   指针/引用操作的典型错误（如空指针解引用、混淆`*`和`&`）。
        *   更新顺序错误（如先移动指针后访问数据）。
        *   对goto跳转逻辑的误解（如误以为跳转到标签后执行之前代码）。
*   **题型判断**：主要使用单选题。若涉及多个正确操作或需要选择多个错误点，可使用多选题。

### **步骤2：答案与格式核查**
1.  **答案合理性核查**：
    *   **合理**：答案准确反映代码实现细节。→ 保留。
    *   **表述不严谨**：修正表述，使其更贴近代码语义。
    *   **逻辑性错误**：废弃该题。
2.  **格式与内容核查**：
    *   **代码引用方式**：题干或选项引用代码时，使用**行内代码**形式（如 `i++`），**绝对禁止使用独立代码块**。
    *   **考点去重**：当用户指示“多出几题”时，基于**最后一次收到的代码内容**，挖掘**新的、未考察过的实现细节**。
    *   **关键转义规则**：**仅选项块内**的方括号`[`或`]`需要转义为`\[`和`\]`。题干和题解中若需显示方括号，正常书写即可。

### **步骤3：“多出几题”指令的响应逻辑**
当用户指示“多出几题”时：
1.  基于**最后一次收到的C++代码内容**出题。
2.  回顾该代码下已生成的所有题目，确保新题的**考点是全新的实现细节**。
3.  出题优先级建议：
    *   第一轮：关键变量操作和赋值。
    *   第二轮：条件判断逻辑和边界处理。
    *   第三轮：循环控制细节（初始化、条件、迭代）。
    *   第四轮：指针/引用操作、内存管理。
    *   第五轮：goto跳转的具体条件和目的。
    *   后续：函数调用细节、数据结构操作等。

## **四、输出格式（必须严格遵守）**

### **核心要求**
**每道题独立包裹在一个单独的 \`\`\`plaintext\`\`\` 代码块中。该块内禁止任何其他类型的代码块嵌套。**

### **题干格式**
*   置于 \`\`\`plaintext 代码块内第一行，以问号结束。
*   **必须明确引用具体的标签名**（如“在`STEP3:`的代码中”）。
*   直接以问题内容开始，无需前缀。

### **选项块格式**
*   **起始标记**：单选题以 `[Choice##` 开头，多选题以 `[Choice#multi#` 开头。
*   **选项标识**：正确选项前用 `*`，错误选项前用 `-`。
*   **结束标记**：以 `]` 结束。
*   **选项内容**：
    *   每个选项单独一行，`*` 或 `-` 后跟一个空格，再接内容。
    *   **关键转义规则**：选项内容中若需使用方括号 `[` 或 `]`，**必须进行转义**，写作 `\[` 和 `\]`。
*   **选项顺序**：正确选项的位置应随机分布。

### **题解格式（可选）**
*   可在选项块后添加 `---` 分隔行，然后编写简短**题解**。
*   **题解重点**：解释该代码片段的**作用**、**必要性**，并指出**常见的实现错误**及其后果。
*   **重要**：题解部分不需要对`[`和`]`进行转义。

### **标准结构示例**

#### **单选题（考察变量操作）**
```plaintext
在标签`INIT:`的代码中，变量`count`被初始化为0，这个操作的目的是什么？

[Choice##
- 为了避免未定义行为，但实际算法中不会用到count
* 作为计数器，用于记录后续循环中满足条件的元素个数
- 为了给数组分配空间
- 用于存储最终结果，初始化为0是随意的
]
---
题解：`count`通常用作计数器。初始化为0是标准做法，以确保从零开始累加。如果不初始化，其值是未定义的，可能导致错误计数。
```

#### **单选题（考察条件判断）**
```plaintext
在标签`CHECK:`中，条件判断`if (i < n && arr[i] > 0)`中的`i < n`部分主要防止什么？

[Choice##
- 防止整数溢出
* 防止数组越界访问（确保i在有效索引范围内）
- 防止除零错误
- 提高代码可读性，实际可以省略
]
---
题解：`i < n`确保索引`i`在访问`arr[i]`前是有效的。如果省略，当`i >= n`时，`arr[i]`将访问数组外的内存，导致未定义行为（崩溃或数据错误）。
```

#### **多选题（考察循环细节）**
```plaintext
在标签`LOOP:`的for循环`for (int i = start; i <= end; i += 2)`中，以下哪些说法是正确的？（多选）

[Choice#multi#
* 循环变量`i`的初始值为`start`
* 循环将一直执行，直到`i`大于`end`
- 每次迭代后，`i`增加1
* 每次迭代后，`i`增加2
- 如果`start`大于`end`，循环体一次也不会执行
]
---
题解：该循环从`start`开始，每次增加2（`i += 2`），当`i`小于等于`end`时继续执行。注意：即使`start > end`，由于是`<=`条件且步长为正，循环体可能不会执行，但更精确的说法是“条件不满足时不执行”，选项表述不够准确。正确选项为第一、二、四个。
```

#### **单选题（考察goto跳转）**
```plaintext
在以下代码片段中：
    COMPARE:
        if (a[i] < pivot) goto LESS;
        else goto GREATER;
    LESS:
        swap(a[i], a[left]);
        left++;
        goto NEXT;
    问题：当条件`a[i] < pivot`成立时，程序会执行哪些操作？

[Choice##
* 交换a[i]和a[left]，然后left加1，然后跳转到NEXT
- 只交换a[i]和a[left]，然后继续执行GREATER标签
- 直接跳转到NEXT，不执行任何操作
- 执行GREATER标签的代码
]
---
题解：当条件成立时，程序跳转到`LESS:`标签，依次执行`swap`、`left++`和`goto NEXT`。不会执行`GREATER:`的代码。
```

1.  **与流程图记忆卡的区分**：本任务只关注**步骤内部的实现细节**，不考察步骤间的顺序和整体结构。
2.  **goto范式的特殊性**：注意考察goto跳转是否跳过变量初始化等C++限制，理解标签的作用范围。
3.  **转义规则**：仅选项块内的方括号需要转义，题干和题解中的方括号正常书写。
